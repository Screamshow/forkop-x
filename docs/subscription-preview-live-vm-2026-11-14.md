# Проверка preview реальной подписки на OpenWrt VM

14 ноября 2026 года. Использована существующая VMware VM `192.168.1.1`, OpenWrt 25.12.5 x86/64; установленное ядро — Xrust 0.0.36. Проверены локальные исправления dev из `tmp/beam-dev`. Пакеты не переустанавливались.

Подписка предоставлена пользователем для этой проверки. URL, токен, тела ответов, ключи узлов и приватные конфигурации в этот отчёт не включены.

## Результаты

- Общий загрузчик скачал реальную HTTPS-подписку напрямую и успешно нормализовал её.
- Полный backend preview — загрузчик, парсер и генератор — вернул 65 записей метаданных, соответствующих 43 уникальным именам для выбора в интерфейсе.
- Загрузка той же подписки через настоящую работающую прокси-секцию также прошла, включая полный backend preview с тем же количеством записей и уникальных имён.
- Для этого в runtime-конфигурацию временно добавлен loopback mixed inbound на порту 4656 с маршрутом в существующую рабочую секцию. Изменение прошло `sing-box check` и применено SIGHUP без смены PID ядра. Это тест настоящего Xrust-прокси, а не локального HTTP-ответчика.
- После удаления тестового inbound preview отверг недоступный выбранный путь, не создал скачанный файл и не перешёл к прямой загрузке. Прямой путь при этом ранее успешно работал.
- В LuCI создана отключённая временная секция с предоставленной подпиской. Сохранённый каталог для проверки восстановления заполнен метаданными, полученными реальным preview; действующие рабочие секции не заменялись.
- В свежезагруженном интерфейсе серверы доступны в фильтре URLTest и уровне Priority даже при отсутствующем proxy-inbound. В обоих диалогах удалось выбрать сервер. Формы не применялись к рабочей конфигурации.
- Затем тестовый кэш убран, proxy-inbound снова временно включён: настоящий сетевой preview из LuCI показал «Серверы подписки: 43».

## Кэш браузера

Первый проход браузера использовал старый JS: после отключения proxy-inbound он воспроизвёл исходную ошибку. Проверка HTTP-файла на VM подтвердила, что исправленный JS установлен, но браузер продолжает использовать прежний ресурс. Для свежего прохода создан временный alias пути ресурсов LuCI с резервной копией `/etc/config/luci`. После смены пути подтверждены новая версия интерфейса и успешный выбор серверов без proxy-inbound. Alias и настройка полностью удалены при восстановлении. Исходники из-за этой проверки не менялись.

## Восстановление

До изменений сохранены установленные пакеты, enabled/running, PID, UCI Forkop/DHCP, конфигурация ядра, исходные заменяемые файлы и firewall snapshot. Конфигурация LuCI дополнительно сохранена перед сменой пути ресурсов.

После тестов:

- SHA-256 совпал с исходным для UCI Forkop/DHCP, runtime-конфигурации, CLI и всех трёх файлов overlay.
- Конфигурация LuCI восстановлена побайтно; alias ресурсов удалён.
- Список установленных пакетов не изменился.
- PID ядра сохранился; Forkop работает и включён в автозапуск. Состояние отдельного сервиса ядра соответствует исходному.
- DNS-запрос через локальный резолвер прошёл.
- Тестовый proxy-inbound и временная UCI-секция удалены.

Приватные входные данные и тела подписки хранились только в локальном ignored tmp и закрытой временной папке VM; после восстановления удалены. Остались только обезличенный отчёт и снимки диалогов без URL/ключей.

## Границы

Это проверка конкретной предоставленной подписки на одной VM и установленном Xrust 0.0.36. Не проверялись все узлы подписки, общая совместимость всех провайдеров, полная CI или установка будущих релизных пакетов. Для preview через выбранную секцию по-прежнему нужен её активный служебный вход; отсутствие такого входа не приводит к применению черновика или прямой загрузке.
